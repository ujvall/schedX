# Phase 3.1 Statistical Audit (post hoc)

> **Audit artifact.** This is a post-hoc review of the committed Phase 3
> results. It does **not** replace the pre-specified Phase 3 analysis and
> does not change the frozen controller, the test split, or any committed
> Phase 3 result file. Numbers are generated by `scripts/audit_phase3.py`
> into [`audit_results.json`](audit_results.json), recomputed from
> `reports/phase3/per_workload_test.csv` without using `schedx.stats`.

Audited inputs: config hash `ae9db57acecd`, dataset `67da9d294be3`, commits
`a13ffba` (freeze) and `4ada3b7` (test evaluation).

## Verdict

* Every committed Phase 3 statistic reproduces exactly. No arithmetic or
  implementation defect was found.
* The disagreement between the bootstrap CI (excludes 0) and the Wilcoxon
  test (p = 0.50) is explained by **different estimands**, not by an error.
* Four **reporting** issues were found; they are corrected in the
  documentation (see "Corrections") without changing committed results.
* The pre-specified conclusion stands: **no statistically supported
  improvement** of the adaptive controller over the best fixed quantum
  (RR1). The evidence is best described as weak and inconclusive, consistent
  with a small mean benefit.

## Integrity checks

* All 9 methods cover the same 300 workloads, with no duplicates and no
  missing values.
* The workload ids equal the test ids of the Phase 2 grouped split, with
  zero overlap with train or validation.
* The `results.json` config hash equals the frozen controller's.
* The pre-specified statistics (Pratt Wilcoxon, the 9-hypothesis Holm

  `a13ffba`. Only the labelled post-hoc `sensitivity()` was added afterwards.
* A full rerun of Phases 2–3 in an isolated directory reproduced every

| Item | Finding |

### Why the CI and the Wilcoxon test disagree

The bootstrap CI and the permutation and t-tests concern the **mean** of
the log ratios. They agree with each other: a small mean improvement, with
the CI just excluding 0 (only 1.6% of bootstrap means are ≥ 0) and p ≈ 0.04
unadjusted. The Pratt Wilcoxon test ranks all 300 absolute differences and
then drops the 275 zeros, so the 25 changed workloads all get ranks 276–300
and carry almost no magnitude information. The test then behaves nearly like
a sign test on 14 better vs 11 worse workloads, and ignores that the gains
are larger than the losses. Both procedures are valid and correctly
implemented; they test different hypotheses. Even the mean-based p-values
are unadjusted. For example, Bonferroni over the 7 distinct deployable
hypotheses would give 7 × 0.042 = 0.29.

## Submission-time controller (raw p = 0.049, Holm 0.29)

The mirror image of the primary case: 46 workloads improved and 28 got
worse, but the improvements are small and the losses larger.

| | Value |

| Sign test | 0.047 |

The marginal raw p-value reflects "improves more often", not "improves on

analyses show no effect. **Not a supported improvement.**

## Reporting issues and corrections

| # | Issue | Correction (documentation only; applied in a separate commit after this artifact) |
|---|---|---|
| 1 | The rank-biserial (−0.43) uses zeros-dropped ranks but is shown next to the Pratt test without qualification in `reports/phase3/summary.md` | `docs/phase3_adaptive_scheduling.md` states both versions (−0.43 zeros dropped; −0.13 Pratt ranks) |
| 2 | "−0.38%" was described as a change in "average turnaround" (README) | README and doc describe it as the geometric mean of per-workload ratios, and also give the change in mean turnaround (−0.17%) |
| 3 | The Holm family includes two duplicate hypotheses | disclosed in the doc, with 7-hypothesis values as a sensitivity check; the committed family is unchanged |
| 4 | The decision rule for "statistically supported" (Holm p < 0.05 **and** CI upper bound < 0) is defined in `scripts/phase3_evaluate.py`, which was written before the single test run but committed after it, and is not in the frozen methodology; subgroup breakdowns use 2,000 resamples, while the doc implied 10,000 | disclosed in the doc's methodology section |

`reports/phase3/summary.md` and `results.json` are committed evidence and
are left unchanged. Issue 1 applies to them as published; read them
together with this audit.
